# 15. 3Sum

[LeetCode problem](https://leetcode.com/problems/3sum/) | [Python solution](./0015_3sum.py) | [Topic guide](./README.md) | [Progress tracker](../PROGRESS_TRACKER.md)

## What the Question Asks

Given integers, return every unique group of three values whose sum is zero.

For example:

```text
input:  [-1, 0, 1, 2, -1, -4]
output: [[-1, -1, 2], [-1, 0, 1]]
```

The answer contains values, not indexes. The same value may be used twice only
when it appears at least twice in the input. Duplicate triplets are not allowed.

## Recognize the Pattern

Look for:

- three values must meet a target sum,
- duplicate answers must be removed,
- sorting lets pointer movement become meaningful.

The pattern is:

```text
sort -> fix one value -> solve a two-value sum with left and right pointers
```

## Start With a Direct Approach

Three nested loops can try every triplet.

```text
first choice:  N possibilities
second choice: N possibilities
third choice:  N possibilities
```

That is `O(N^3)` time. It also needs extra work to avoid duplicate answers.

After fixing one value, the remaining problem is a sorted two-sum problem. Two
pointers solve that remaining work in `O(N)`, giving `O(N^2)` overall.

## Two Pointers From Scratch

In a sorted list:

```text
small values                         large values
     left ------------------------------- right
```

For a fixed first value:

- If the total is too small, move `left` right to get a larger value.
- If the total is too large, move `right` left to get a smaller value.
- If the total is zero, save the triplet and move both pointers.

Sorting is what proves these moves are safe. Moving the other direction would
make an already wrong total even worse.

## The Invariant

For one fixed index, every untested pair that can still be an answer lies between
`left` and `right`.

Each comparison safely removes at least one impossible endpoint. The pointers
never move backward, so the pair scan is linear.

## Avoid Duplicate Triplets

Duplicates can enter in two places.

1. If the fixed value equals the previous fixed value, skip it. Its pairs were
   already explored.
2. After finding a triplet, move both pointers past repeated values before
   searching again.

For `[0, 0, 0, 0]`, this produces one `[0, 0, 0]`, not several copies.

## Step by Step

1. Create a sorted copy of the input.
2. Move `first` from left to right, stopping with room for two more values.
3. Skip a repeated fixed value.
4. Stop early if the fixed value is positive. Every later value is also positive.
5. Set `left = first + 1` and `right = last index`.
6. Compare the three-value total with zero.
7. Move the pointer that makes the total move toward zero.
8. Save an exact match and skip duplicate endpoint values.

## Dry Run

Sorted values are `[-4, -1, -1, 0, 1, 2]`.

Fix the first `-1`:

| Fixed | Left | Right | Total | Action |
| ---: | ---: | ---: | ---: | --- |
| -1 | -1 | 2 | 0 | Save `[-1, -1, 2]`; move both |
| -1 | 0 | 1 | 0 | Save `[-1, 0, 1]`; move both |

The next fixed value is also `-1`, so it is skipped. No duplicate triplets are
created.

## Python Used Here

```python
values = sorted(nums)
```

`sorted` returns a new list. It does not change `nums`.

```python
triplets.append([values[first], values[left], values[right]])
```

`append` adds one triplet list to the answer list.

## Why It Is Correct

For each unique fixed value, the two pointers begin at the smallest and largest
remaining values. A total below zero cannot be repaired by decreasing the right
value, so increasing the left value safely removes the current left endpoint. A
total above zero similarly requires decreasing the right value. An exact total
is saved.

Therefore the scan finds every pair that completes the fixed value. Duplicate
fixed and endpoint values are skipped only after their equal-valued possibility
has already been processed, so no unique value triplet is lost.

## Complexity

New to Big-O? Read [Time and Space Complexity for Beginners](../python_basics/11_time_and_space_complexity.md).

Let `N` be the number of input values.

- Sorting costs `O(N log N)` time.
- Up to `N` fixed positions each perform an `O(N)` pointer scan.
- Total time is `O(N^2)`, which dominates sorting.
- The sorted copy uses `O(N)` extra space.
- Returned triplets are normally excluded when stating auxiliary space.

## Assumptions to Say Aloud

- The answer needs value triplets, not original indexes.
- Triplet order and answer order do not matter unless the interviewer says they do.
- The input may contain negative, zero, positive, and duplicate values.
- This implementation keeps the input unchanged by sorting a copy.

## Edge Cases

- Fewer than three values returns an empty list.
- All values are positive or all are negative.
- Several zeros produce only one zero triplet.
- The answer needs two equal values, such as `[-2, 1, 1]`.
- Many repeated values must not create repeated triplets.
- No valid triplet exists.

## Common Mistakes

- Using a two-pointer scan before sorting.
- Returning indexes as in Two Sum instead of value triplets.
- Skipping every repeated value before it has had one chance to participate.
- Moving only one pointer after finding an answer.
- Forgetting that `list.sort()` mutates the caller's list.
- Claiming `O(N log N)` because sorting is visible while missing the nested scan.

## Possible Follow-up Questions

| Follow-up | Answer Direction |
| --- | --- |
| Find triplets for target `T`. | Compare the total with `T` instead of zero. |
| Find the closest triplet sum. | Track the smallest absolute difference while scanning every fixed value. |
| Return original indexes. | Sorting loses direct positions, so sort `(value, index)` pairs and define duplicate-index behavior. |
| Solve 4Sum. | Fix two values, then run two pointers; time becomes `O(N^3)`. |
| Can you avoid the sorted copy? | Sort in place for lower auxiliary space, but state that the input is mutated. |

## Interview Explanation

> I sort a copy, fix one value, and solve the remaining two-sum problem with a
> left and right pointer. If the total is low I increase the left value; if it is
> high I decrease the right value. I skip equal fixed values and equal endpoints
> after a match so each value triplet appears once. The nested fixed-value and
> pointer scans take `O(N^2)` time, and the sorted copy uses `O(N)` extra space.

What does the algorithm return for `[-2, 0, 1, 1, 2]`?

**Answer:** `[[-2, 0, 2], [-2, 1, 1]]`.

After sorting, fix `-2`. The endpoints `0` and `2` complete the first triplet.
Moving inward reaches the two separate `1` entries, which complete the second.
Fixing later values cannot create a new unique zero triplet.

The repeated value `1` is valid in one answer because the input contains it at
two different indexes. Duplicate removal concerns repeated answer values, not a
ban on equal elements.

**Complexity:** The full algorithm remains `O(N^2)` time and `O(N)` auxiliary
space for the sorted copy.

### Question 2: Pair Sum in a Sorted List

Return whether a sorted list contains two different values that add to `target`.

<details>
<summary>Show answer and detailed solution</summary>

```python
def has_pair_sum(values: list[int], target: int) -> bool:
    left = 0
    right = len(values) - 1

    while left < right:
        total = values[left] + values[right]

        if total == target:
            return True
        if total < target:
            left += 1
        else:
            right -= 1

    return False
```

Because the list is sorted, a low total proves the current smallest endpoint is
too small with every remaining right value. A high total proves the current
largest endpoint is too large with every remaining left value.

**Complexity:** `O(N)` time and `O(1)` extra space.

**Tests:** `has_pair_sum([1, 2, 4, 7], 6)` is `True`; target `20` is `False`;
an empty or one-item list is `False`.

</details>
